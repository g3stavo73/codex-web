==================================================
1. OBJETIVO PRINCIPAL
==================================================

Construir uma aplicação web capaz de utilizar o Codex real,
por meio do Codex App Server.

O objetivo não é criar apenas uma interface visual que
simula o ChatGPT ou o Codex.

Queremos construir uma aplicação funcional na qual o usuário
possa enviar tarefas para o Codex, acompanhar sua execução,
receber respostas, trabalhar com projetos e utilizar
ferramentas de desenvolvimento.

O núcleo do Codex Web deve funcionar antes de investirmos
em recursos secundários.

A aplicação deverá evoluir para oferecer uma experiência
de desenvolvimento integrada, com conversas, projetos,
arquivos, terminal, Git, agentes e plugins.

==================================================
2. ARQUITETURA PRINCIPAL
==================================================

A arquitetura utiliza três tecnologias principais:

C# / ASP.NET CORE:
- É o cérebro da aplicação.
- Controla as regras de negócio.
- Gerencia sessões e tarefas.
- Coordena os serviços.
- Controla a comunicação entre os componentes.
- Gerencia a autenticação e as operações do backend.

PYTHON:
- Atua como camada auxiliar de integração.
- Auxilia na comunicação com componentes externos.
- Trabalha com contexto de repositórios.
- Gerencia integrações e MCP.
- É coordenado pelo backend C#.

CODEX APP SERVER:
- É o runtime responsável pela execução real do Codex.
- Gerencia threads e turns.
- Recebe tarefas.
- Executa o trabalho solicitado.
- Emite eventos de execução.
- Fornece os resultados.

JAVASCRIPT:
- Controla a interface do usuário.
- Manipula o DOM.
- Envia requisições para a API C#.
- Recebe e apresenta as respostas.
- Não deve conter regras de negócio.

==================================================
3. REGRAS ARQUITETURAIS
==================================================

1. C# é a tecnologia principal do backend.

2. Python não substitui o backend C#.

3. O Codex App Server é o runtime real do Codex.

4. JavaScript não deve implementar a lógica principal
   da aplicação.

5. Não colocar credenciais, tokens ou chaves de API
   no frontend.

6. Não implementar comunicação direta do navegador
   com o Codex App Server.

7. Evitar duplicação de responsabilidades.

8. Não criar abstrações sem necessidade.

9. Toda implementação deve considerar a compatibilidade
   com os arquivos já existentes.

10. Não fingir que uma funcionalidade está implementada
    quando ainda não está.

==================================================
5. FUNCIONAMENTO DO CODEX
==================================================

O conceito central utiliza três elementos:

SESSION:
Representa uma conversa no Codex Web.

THREAD:
Representa a conversa correspondente no Codex App Server.

TASK:
Representa uma solicitação individual do usuário.

TURN:
Representa a execução correspondente à tarefa no Codex.

Relação:

CodexSession -> Codex Thread
CodexTask -> Codex Turn

Uma sessão pode conter várias tarefas.
Cada tarefa pertence a uma sessão.
Cada tarefa executa um turn dentro da thread
correspondente.

O backend deve preservar essa relação.

==================================================
6. ENTIDADES E INTERFACES
==================================================

ENTIDADES:

CodexSession.cs
- Identificador interno.
- Título.
- Identificador da thread do Codex.
- Estado da sessão.
- Datas de criação e atualização.
- Operações de gerenciamento da sessão.

CodexTask.cs
- Identificador interno.
- Identificador da sessão.
- Prompt.
- Identificador do turn do Codex.
- Estado da tarefa.
- Motivo de falha.
- Datas de execução.

INTERFACES:

ICodexRuntime.cs
- Inicializar o runtime.
- Criar threads.
- Retomar threads.
- Iniciar turns.
- Solicitar interrupções.
- Ler eventos emitidos pelo runtime.

ITaskExecutor.cs
- Coordenar o início das tarefas.
- Coordenar solicitações de interrupção.
- Atualizar o ciclo de vida das tarefas.

As interfaces devem manter responsabilidades
separadas e não duplicar a implementação
da comunicação com o Codex.

As exceções devem representar condições reais
que possam ser tratadas pelo backend.

Evitar criar exceções desnecessárias.

==================================================
8. CODEX APP SERVER
==================================================

A integração deve respeitar o protocolo oficial
do Codex App Server.

Conceitos importantes:

- initialize
- initialized
- account/read
- account/login/start
- thread/start
- thread/resume
- turn/start
- turn/interrupt
- turn/completed
- item/agentMessage/delta

A comunicação utiliza JSON-RPC.

O backend deverá lidar com:
- Inicialização.
- Comunicação.
- Identificadores de threads e turns.
- Notificações.
- Eventos incrementais.
- Erros.
- Interrupções.
- Encerramento da conexão.

Não inventar métodos ou parâmetros.
Consultar a documentação oficial antes de implementar
operações do protocolo.

Documentação:
https://learn.chatgpt.com/docs/app-server

Autenticação:
https://learn.chatgpt.com/docs/auth?surface=cli
